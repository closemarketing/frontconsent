# FrontConsent Repository for WordPress Plugin

Repository for FrontConsent, a WordPress plugin providing a GDPR/ePrivacy-compliant cookie consent banner, following the Spanish AEPD guide.

## Functionalities

- **Cookie Notice** — configurable cookie consent banner (bar/box/popup) that gates Google Tag Manager, GA4, and supported tracking integrations (Clientify, Brevo, ChatGPT Ads) behind consent, with Google Consent Mode v2 support for compatibility with Google Site Kit and other analytics plugins.
- **Cookie preferences panel** — a "Customize cookie settings" button (left of Reject/Accept) and the persistent reopen trigger both open a dialog with Accept all / Reject all / Save changes and a static "Strictly necessary" section, all recording the exact same consent cookie/Consent Mode update/logging as the binary Accept/Reject buttons. Extensible via the `frcn_cookie_preferences_categories` action and `frcn_cookie_consent_categories` filter so FrontConsent PRO can add per-category consent (Analytics, Marketing, etc.) without forking markup — see [docs/preferences-panel-hooks.md](docs/preferences-panel-hooks.md).
- **Per-category consent (Analytics / Marketing)** — two real toggles in the preferences panel, stored in the `frontconsent_categories` cookie. They drive which tracking integrations load, the granular Google Consent Mode signals (`analytics_storage` from Analytics, `ad_*` from Marketing), the script/iframe blocker, and which cookies get deleted. Lowering a choice reloads the page so tags already running stop.
- **Cookieless video embeds** — YouTube iframes are switched to `youtube-nocookie.com` and Vimeo iframes get `dnt=1`, so embedded videos set no cookies before consent (filter `frcn_privacy_enhanced_embeds`).
- **Acceptance stats** — aggregate accepted/rejected counter on the settings page.
- **Script & Iframe Blocking** — a settings-configured list of match-pattern/category rules holds back any matching `<script src="...">` or `<iframe src="...">` (YouTube, Maps, social widgets, custom tracking snippets, etc.) until the visitor accepts, via output-buffered HTML rewriting server-side and placeholder revival client-side.
- **Migration from FrontBlocks** — automatically imports settings and stats from FrontBlocks Site Tools' bundled Cookie Notice module, which FrontConsent replaces. It also switches off FrontBlocks PRO's legacy cookie categories module once, since that module only hooks FrontBlocks' retired banner and would otherwise print an unreachable dialog.
- **Import from GDPR Cookie Compliance** — explicit "Import settings" action that maps its Integrations tab (GA4, GTM, and the container configured in GTM4WP) and banner texts/expiration/position into FrontConsent without overwriting existing values; unsupported integrations (Google Ads, Meta Pixel, Microsoft UET/Clarity, reCAPTCHA) are reported, not imported. See `includes/GDPR_Cookie_Compliance_Migration.php`.
- **Consent-gated attribution cookies** — WooCommerce order attribution scripts (`sbjs_*` cookies) stay inert until the visitor accepts (filter `frcn_cookie_notice_gated_script_handles`), and GTM4WP's own Consent Mode default is suppressed so FrontConsent's denied default is the only one (filter `frcn_cookie_notice_suppress_gtm4wp_consent_default`).
- **Tracking cookies deleted on rejection** — rejecting, withdrawing an earlier acceptance, or returning after a rejection deletes known analytics/marketing cookies (`_ga`, `_ga_*`, `_gid`, `_gcl_*`, `_fbp`, `sbjs_*`…) on the host and its parent domains, so nothing set while consent was granted stays behind (filter `frcn_cookie_notice_purge_cookies`).
- **Extensible settings tabs** — the settings page renders as a tab shell (Settings, plus a PRO upsell tab by default). A companion plugin such as FrontConsent PRO can add its own tab via the `frontconsent_settings_tabs` filter and render its panel on the `frontconsent_settings_form_tab_panels` action (fields saved through the main form) or `frontconsent_settings_tab_panels` action (a panel with its own form, e.g. a License tab).
